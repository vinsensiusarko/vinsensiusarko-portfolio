## Numbered Findings (Choose Which Numbers to Fix)

### 1. [Important | Accessibility & Mobile] `AdminSkillsTab` lacks keyboard & touch reordering controls
- **Where:** `src/pages/admin/tabs/AdminSkillsTab.jsx` (`renderSkillRow`, lines 408-485)
- **Issue:** Unlike `AdminProjectsTab` (which provides Move Up / Move Down buttons alongside drag-and-drop), `AdminSkillsTab` only supports HTML5 mouse Drag-and-Drop. Keyboard-only users and mobile touch users cannot reorder skills within a category.
- **Suggested Fix:** Add accessible Move Up / Move Down icon buttons (`IconArrowUp` / `IconArrowDown`, disabled at category boundaries and during `isReordering`) to each skill row, reusing the exact category-isolated optimistic + Firestore batch logic.

### 2. [Important | Mobile Layout] Secondary Admin action buttons fall below 44x44px touch target on mobile viewports
- **Where:**
  - `src/pages/admin/AdminPage.jsx` (topbar `View Live Site` `h-9` & theme toggle `size-9`)
  - `src/pages/admin/tabs/AdminProjectsTab.jsx` (card Up/Down/Edit/Delete `size-8` / `h-8`, gallery buttons `size-8`)
  - `src/pages/admin/tabs/AdminSkillsTab.jsx` (level toggle `h-7`, Edit/Delete `size-8`, preset chips `h-7`)
  - `src/pages/admin/tabs/AdminSeoTab.jsx` (platform switcher `h-8`)
- **Issue:** On touch devices (`<sm` viewport), 28px to 36px buttons increase tap errors (`antislop-layoutmobile` 44px minimum touch target guideline).
- **Suggested Fix:** Apply responsive touch sizing (`min-h-11 sm:min-h-0` / `size-11 sm:size-8` or `h-10 sm:h-8`) so mobile gets comfortable 44px hit areas while desktop preserves dense studio ergonomics.

### 3. [Important | Data Honesty] `AdminAnalyticsTab` omits the `Other` bucket from Browser & OS breakdown lists
- **Where:** `src/pages/admin/tabs/AdminAnalyticsTab.jsx` (lines 366-412)
- **Issue:** `totalBrowserViews` and `totalOsViews` include `Other` in their denominators, but the UI only renders `['Chrome', 'Safari', 'Firefox', 'Edge']` and `['Windows', 'Android', 'iOS', 'macOS', 'Linux']`. Whenever `Other > 0` (including after clicking **Seed Demo Data**), the visible percentages do not sum to 100%.
- **Suggested Fix:** Conditionally include `'Other'` in Browser Distribution and Operating Systems whenever `Number(map.Other || 0) > 0` so breakdowns sum honestly to 100%.

### 4. [Medium | Semantics & Accessibility] Heading hierarchy skips/misuses in `AdminAnalyticsTab` and `AdminSeoTab`
- **Where:**
  - `src/pages/admin/tabs/AdminAnalyticsTab.jsx` (line 266: `<h3>` wraps bare KPI number `1,250` instead of `<p>`)
  - `src/pages/admin/tabs/AdminSeoTab.jsx` (lines 252, 263, 275: social preview cards jump from `<h2>` to `<h4>` with no `<h3>`)
- **Issue:** Screen readers navigating by headings hear raw numbers (`"1,250"`) as section headings in Analytics and skipped heading levels (`h2 -> h4`) in SEO Preview.
- **Suggested Fix:** Render KPI figures in `AdminAnalyticsTab` as `<p>` (with label above in semantic `<dt>`/`<span>`), and use `<p className="text-sm font-semibold">` (or `<h3>`) inside `AdminSeoTab` social preview frames.

### 5. [Medium | React Architecture] Redundant nested `ConfirmProvider` and `TooltipProvider` in `AdminPage.jsx`
- **Where:** `src/pages/admin/AdminPage.jsx` (lines 415, 629) vs `src/App.jsx` (lines 37, 39)
- **Issue:** `App.jsx` already wraps all routes in `<ConfirmProvider>` and `<TooltipProvider>`, so navigating to `/admin` mounts a second nested instance of both providers (extra portal/state overhead).
- **Suggested Fix:** Remove the duplicate `<TooltipProvider>` and `<ConfirmProvider>` from `AdminPage.jsx` (and wrap `<AdminPage />` with those providers inside `AdminPage.test.jsx` when rendered standalone).

### 6. [Low | Code Hygiene] Unused Next.js `"use client"` directives in Vite SPA primitives
- **Where:** `src/components/ui/select.jsx` (line 1), `src/components/ui/progress.jsx` (line 1)
- **Issue:** Generated shadcn files included `"use client"` even though this repository is a Vite React SPA (none of the other 18 primitives use it).
- **Suggested Fix:** Remove `"use client"` from `select.jsx` and `progress.jsx` for consistency across `src/components/ui/`.

### 7. [Low | Copy Consistency] Mixed Indonesian and English copy in Admin descriptions & upload helper hints
- **Where:**
  - `src/pages/admin/tabs/AdminDatabaseTab.jsx` (Backup & Seeder card descriptions in Indonesian while titles, buttons, and stats are English)
  - `src/pages/admin/tabs/AdminSkillsTab.jsx` (upload helper text in Indonesian while modal title, labels, and tabs are English)
- **Issue:** Switching languages mid-sentence inside the same card feels slightly uneven (`antislop-copywriting` voice consistency).
- **Suggested Fix:** Unify Admin CMS body copy to clean English (while preserving specific labels covered by existing tests such as `Pakai Asset Favicon Arko` and `Batal`).
