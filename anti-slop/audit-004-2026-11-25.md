## Numbered Findings (Choose Which Numbers to Fix)

### 1. [Medium | Readability / Typography] Sub-11px (`text-[10px]`) labels inside `DeviceFrame` chrome
- **Where:** `src/components/common/DeviceFrame.jsx` (lines 65 & 91)
- **Issue:** Both the desktop window title bar and the web browser address bar pill use `text-[10px]`, which is slightly below comfortable legibility on mobile and high-DPI displays.
- **Suggested Fix:** Bump `text-[10px]` to `text-[11px]` (keeping `truncate` and `font-mono`) so URLs and window titles remain crisp and legible without expanding frame chrome height.

### 2. [Medium | Accessibility / WAI-ARIA Consistency] `ProjectsSection` filter tabs lack arrow-key roving focus (unlike `JourneySection`)
- **Where:** `src/components/sections/ProjectsSection.jsx` (lines 250-291)
- **Issue:** `JourneySection` implements the complete WAI-ARIA Tabs pattern (`ArrowRight`/`ArrowLeft`/`Home`/`End` navigation, `tabIndex` roving focus, `aria-controls` + `role="tabpanel"`), while `ProjectsSection`'s category `role="tablist"` relies only on click/Tab without arrow-key navigation or tabpanel association.
- **Suggested Fix:** Add the same roving keyboard handler (`ArrowRight`/`ArrowLeft`/`Home`/`End`), `tabIndex={isActive ? 0 : -1}`, `id`/`aria-controls`, and `role="tabpanel"` association to `ProjectsSection` so both filterable sections on the landing page behave consistently for keyboard and screen-reader users.

### 3. [Low | Mobile Layout Polish] Gallery Prev/Next arrows overlap `DeviceFrame` side edges on narrow screens (`360px`)
- **Where:** `src/components/sections/ProjectModal.jsx` (line 222)
- **Issue:** When a multi-image project (`hasGallery === true`) is viewed with `showFrame === true` on a narrow phone (`360px`), the `left-3`/`right-3` `size-11` (`44px`) Prev/Next arrows overlap the left and right edges of `web` / `desktop` `DeviceFrame` because the framed container uses `px-4` (`16px`) horizontal padding.
- **Suggested Fix:** When `hasGallery && showFrame`, apply wider horizontal gutter padding (`px-14 sm:px-16`) on the framed preview container so Prev/Next controls sit cleanly beside the device chrome without obscuring the screenshot.

### 4. [Low | Admin Copy Clarity] `AdminProfileTab` submit CTA wording omits Availability & Timeline
- **Where:** `src/pages/admin/tabs/AdminProfileTab.jsx` (lines 317 & 871)
- **Issue:** After adding the Availability Status and Career & Education Timeline sections to `AdminProfileTab`, the submit button still reads `Save Profile & Bio Changes`, which can leave an admin wondering whether timeline edits are saved by that button.
- **Suggested Fix:** Update the button label to `Save Profile & Timeline` and the success toast to `Profile, availability & timeline saved!` (updating the corresponding assertion in `test/pages/admin/AdminSettingsTabs.test.jsx`).
